# Hybrid experiment and reproduction

This records the completed CPU run. The user requested stronger history, retrieval, model training and identity protection; the assistant ran the experiment. MiniLM and the cross-encoder are pretrained and unchanged. The model trained here is the query-grouped author LambdaRank ranker, not a fine-tuned language model. A GPU or notebook was not required. Runtime uses the exported trees and does not require LightGBM; install `requirements-training.lock` for training.

## Pipeline and temporal protocol

The checksummed DBLP archive is scanned in full. The existing 150,000-paper source-order slice is retained and supplemented with papers from predeclared ML, retrieval and web venue families. No target author is used to choose history. The historical source has 203,842 papers; the through-2018 graph has 160,820 papers and 197,282 authors. Its 1,772,478 author–paper, author–venue and coauthor edge events have dated source evidence; the integrity audit found no unsupported edges. Train labels use 2019–2020 and validation uses 2021–2022.

The inference-only source adds selected 2019–2024 venue history: 272,592 source papers and a 265,885-paper, 332,611-author through-2024 graph with 3,872,790 sourced edge events. A deterministic 1,000 of 5,588 eligible 2025–2026 label queries were selected without using outcomes; source-key/title overlap was checked. Training and selection used the 2018 graph; inference on the newer graph is a rolling transfer, not the same-snapshot test. [Data lineage and audits](../results/hybrid-data-pipeline-v1.json), [plan](../experiments/final-evaluation-plan.json), [freeze](../experiments/hybrid-freeze-v1.json).

A query retrieves lexical and dense papers and recent-paper author profiles; it also expands bounded sourced collaborator neighborhoods. The candidate pool is capped at 400. Features include title/topic relevance, historical support and up to 64 pretrained cross-encoder paper comparisons. A locally trained 80-tree, seven-leaf LambdaRank model blends its score with the hybrid prior. Training used 75,272 examples, including 2,440 positive examples, from 1,138 usable queries out of 3,000 sampled. Non-authors are unjudged contrasts. Model selection used the 400 validation queries only. Its selected feature ablation omits two explicit graph features; graph-based candidate expansion remains active. [Training report](../results/hybrid-validation-v1.json).

## Results and interpretation

On the frozen 1,000-query cohort, nDCG@10/MRR were lexical .03859/.04965, dense .03653/.04887, untrained hybrid .04224/.05549, and selected learned hybrid .05432/.07696. MRR uses each returned list up to 400. Candidate recall was 14.68% for all 4,271 relevant author instances and 26.83% for the 2,337 with historical evidence. These are future-authorship proxy labels, not a measurement of hiring quality. Sequential warm-query p50/p95 were 486/594 ms across 20 samples on this machine; they do not establish throughput or production latency.

The full-feature model scored .05552/.08014, but the without-graph-feature model had already been selected on validation and remains the reported selected model. This small test difference does not justify selecting on the test set. Feature ablations share candidate generation and the hybrid prior: the graph ablation does not remove graph expansion, and the cross ablation removes explicit cross-encoder features, not all other components. [Final report](../results/hybrid-final-v1.json).

The old end-to-end system scored .00179/.00426 on these same queries, but used an older 2018/50k-derived graph, different retrieval and a different model. The comparison measures the combined system change, not an isolated model gain. [Paired comparison](../results/hybrid-final-paired-comparison.json). Query bootstrap intervals do not account for dependence among topics, venues or authors. This is a selected DBLP slice, not an external field test; pretraining overlap cannot be excluded.

The conservative identity policy on 1,697 sampled held-out observations made 151 assignments, 150 correct and one incorrect; precision 99.34% and known-author recall 22.97%. Strict made 39 correct assignments and no observed errors, but known-author recall was 5.97%. These finite synthetic-corruption tests do not prove open-world identity quality. [Identity report](../results/identity-history-holdout-default.json).

## How to reproduce or extend

1. Set up `.venv` from `requirements.lock` and install `requirements-training.lock` for training. Provide the exact DBLP archive and matching MD5 at `data/raw/dblp.xml.gz` and `data/raw/dblp.xml.gz.md5`. The archive, graphs, indexes and feature caches under `data/` are not included in a source-only checkout. Obtain the pinned model assets documented in `models/` if absent. Allow substantial CPU time and disk space.
2. Rebuild the 50k and 150k parent experiments as described in [the workbook](model-training-workbook.md) and [pilot](model-selection-and-pilot.md). They supply baseline source and fixed labels. Run `PYTHONPATH=src .venv/bin/python scripts/enrich_history.py --config experiments/history-enrichment.json --out <new-source.xml>` and then similarly with `experiments/recent-history.json`. The latter config references the historical output at its configured path. The historical scan ran while unrelated package files were being edited; source and config hashes are recorded, but a fully frozen-code rerun would strengthen provenance.
3. Ingest each resulting XML with `hiresense.cli ingest`, prepare the dated historical datasets/snapshots, build sourced edges with `hiresense.cli graph`, then indexes with `hiresense.cli index`. Use `python -m hiresense.cli <command> --help` for current arguments. Existing index vectors can be reused only after manifest validation. Transfer the fixed parent labels to the 2018 graph using `scripts/transfer_cohort.py --help`. The named paths and artifact hashes for this run are in the configurations, manifests and reports; do not overwrite them when experimenting.
4. Run `PYTHONPATH=src .venv/bin/python scripts/train_hybrid.py --config experiments/hybrid-training.json` with a copied configuration pointing to fresh work/report paths. Check cache manifests if reusing features. The saved selected model is `models/hybrid_ranker.json`; `models/expert_ranker.json` is the old baseline. Training/validation source hash in the report was consistent throughout.
5. Before looking at a new test, predeclare its time boundary and selection rule. Prepare the rolling cohort with `scripts/prepare_rolling_test.py --help`, freeze models and artifact hashes with `scripts/freeze_hybrid.py --help`, then run `scripts/evaluate_hybrid.py --freeze <freeze.json> --out <new-report.json>`. The previous-system and paired-comparison scripts reproduce the combined comparison. Never select or tune on this reported test: after inspection it is no longer untouched for a future experiment.
6. For quick functional checks run `./run --data examples/sample.xml --queries examples/queries.txt --out /tmp/hiresense-results.json`. For a portable sample backend use the `prepare-backend` command in the README. The large `experiments/backend.json` needs the locally built 2024 graph and index. Run `scripts/check_clean_copy.py` and `scripts/check_backend.py` with new report paths; the latter needs loopback access. The different-field unseen XML check was functional only, not a ranking benchmark: [report](../results/unseen-systems-hybrid-check.json).

The feature cache was validated against its manifest and five independently recomputed query rows after interruption. Quantized inference can vary slightly with batch padding. The graph's canonical DBLP identities inherit source disambiguation quality, and conservative matching abstains frequently. More representative historical coverage, better retrieval for known authors, independently judged relevance and broader identity evaluation remain necessary. Frontend, deployment and submission deliverables are outside this experiment.
